# 한글또박 발음 지도 앱

초등학교 교실에서 바로 쓸 수 있도록 만든 한글 발음·읽기 진단 앱입니다. 학생이 화면에 나온 글자를 듣고 따라 말하면 Azure AI Speech가 발음을 채점하고, 선생님은 반/학생을 관리하며 결과를 확인·인쇄할 수 있습니다.

**배포 주소**: https://hangeul-phi.vercel.app/

## 학습 단계 (총 8단계)

1. 모음 → 2. 자음 → 3. 받침 없는 단어 → 4. 이중모음 → 5. 이중모음 단어 → 6. 대표받침 → 7. 문장 → 8. 짧은 문단

1~6단계는 자모 단위로 정확히 맞혔는지 직접 비교해서 채점하고(받침 탈락/교체/첨가, 초성·중성 오류까지 구분), 7~8단계(문장/문단)는 자연스러운 억양·연음이 정상이라 Azure의 종합 발음 점수를 그대로 신뢰하는 방식으로 채점합니다.

## 주요 기능

- 로그인(이름+비밀번호 또는 구글 계정), 반/학생 관리, 엑셀 명단 업로드
- 문항별 듣기(모범 발음 TTS) → 마이크로 따라 말하기 → 자동 채점
- 학생별 결과 확인, 오류 유형 진단(받침 탈락 등), 단계별 지도 방안 자동 생성
- 인쇄 가능한 검사지 리포트, 학급 전체 통계(응시율/한글 해득수준/단계별 평균 그래프)

## 기술 스택

- **프론트엔드**: 단일 `index.html` (프레임워크 없이 바닐라 JS) — 더블클릭으로도 열리는 걸 우선했던 원칙에서 출발했으나, 서버 기능(로그인·DB)이 필요해지면서 Vercel 배포로 전환됨
- **음성 인식/발음 평가**: Azure AI Speech REST API (Pronunciation Assessment)
- **인증/데이터베이스**: Supabase (Auth + Postgres, Row Level Security로 "선생님 본인 반만" 접근 제한)
- **배포**: Vercel (서버리스 함수 `api/get-token.js`가 Azure 키를 감추고 임시 토큰만 내려줌)
- **그 외**: Chart.js(학급 통계 그래프), SheetJS(엑셀 업로드/다운로드)

## 로컬에서 실행하기

```
node dev-server.mjs
```

`http://localhost:3000` 접속. Azure 키(`AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`)와 Supabase 키는 `.env.local`에 저장하며 git에는 포함하지 않습니다.

## 개발 회고 — 무엇을 가장 많이 요구했나

이 앱은 Claude Code와의 대화로 만들었습니다. 며칠간 오간 요청들을 되짚어보면 몇 가지 패턴이 뚜렷하게 반복됐습니다.

### 1. UI·가독성 다듬기 — 가장 많이 반복된 요청

전체 요청 중 빈도로 보면 압도적 1위였습니다. 기능이 새로 생길 때마다 "일단 되게" 만든 뒤, 실제로 써보고서야 보이는 문제들을 계속 다듬었습니다.

- 표/버튼 줄바꿈이 한글 특성상 글자 중간에서 끊기는 문제 (예: "다문화"가 "다문/화"로 쪼개짐) → `word-break: keep-all`로 어절 단위 줄바꿈 정리
- 좁은 카드(480px)에 4~5열짜리 표를 욱여넣어 글자가 한 자씩 줄바꿈되던 문제 → 화면별로 넓은 레이아웃 적용, 표 스타일 통일
- "오답 문항/인식된 소리"를 한 칸에 여러 줄로 몰아넣던 방식 → 문항 하나당 표의 행을 따로 만드는 구조로 재설계 (총 2차례 개편)
- 표 줄무늬(zebra striping) 추가 → hover 강조와 색이 겹쳐서 다시 제거
- 오류 유형별 학생 목록을 노란 알약(배지) 모양으로 만들었다가 "다른 표들처럼 깔끔하게" 요청으로 일반 표로 재변경
- 학생 목록/검사 결과 표를 가운데 정렬로 통일, 이름 아래 해득수준 배지 추가
- 화면마다 제각각이던 제목 스타일을 공통 클래스로 통일
- 전체적으로 "너무 둥글둥글해서 바이브 코딩 느낌이 난다"는 피드백으로 버튼/카드 모서리를 각지게 조정

### 2. 채점 기준 / 등급 수립

교육적으로 가장 신경 써서 여러 번 다시 정의한 부분입니다.

- 정확한 단어를 말해도 Azure 점수가 90점대라 100점이 아닌 게 혼란스럽다는 피드백 → 90점 이상은 100점 처리, 90점 미만만 실제 이유를 보여주는 절충안으로 확정
- "자음 하나 틀렸는데 50점은 너무 후하지 않냐"는 문제 제기 → 초성·중성 자체가 다른 오류(완전히 다른 소리, 0~29점)와 받침만 다른 오류(40~69점, 70점 이상은 못 넘게 상한)를 명확히 분리하는 채점 등급 신설
- "한글 해득 수준"(해득/보충/미해득/미검사) 기준을 두 차례 구체화: 처음엔 단순 평균 점수 70/50점 경계였다가, "1단계만 풀고 100점 받은 학생과 6단계를 전부 통과한 학생이 똑같이 해득으로 묶이는" 문제를 발견해 **6단계를 모두 완주해야 해득**으로 기준을 다시 세움 (참고 자료의 "찬찬한글 최종평가" 개념을 근거로 삼음)
- 문장/문단 단계를 추가하며 "이 채점 기준을 그대로 쓸지"를 다시 논의 → 문장은 자연스러운 발화 변이가 정상이라 자모 단위 엄격 채점 대신 Azure 종합 점수를 신뢰하는 별도 방식을 새로 정함

### 3. 오류 진단 문구 / 지도 방안

- "오류 내용"을 07/08번 참고자료 용어(받침 탈락, 초성 오류 등)로 전문적으로 표기해달라는 요청 → 자모 단위로 직접 비교해 태그를 매기는 진단 함수 신설
- 지도 방안 문장이 설명체와 지시체가 섞여 있다는 피드백 → 전부 "~연습시켜보세요"로 끝나는 실행 지침 형태로 통일, 오류 유형별 구체적 지도법 추가
- 뻔한 문구가 반복돼서 지저분하다는 피드백 → 태그만으로 이미 설명되는 문구는 생략하고 진짜 추가 정보가 있을 때만 노출
- 지도 방안 항목 번호가 단계 이름의 번호와 겹쳐 보인다는 지적 → 중복 번호 제거

### 4. 화면 이동 편의 (버튼 추가)

- 결과 화면 어디서든 "학생 목록으로" 한 번에 갈 수 있는 버튼 추가
- 검사 결과 화면에 "리포트" 버튼 추가 (기존엔 학생 목록에서만 진입 가능했음)
- 상단 로고를 누르면 로그인 직후 화면(반 목록)으로 돌아가도록 추가
- "이전 문제" 버튼을 없애고 "모르겠어요" 버튼으로 교체 (학생이 모르는 문항을 넘기면 기록에 남도록)

### 5. 기능 확장

원래 1~6단계 프로토타입만 계획했다가, 실사용 맥락에서 자연스럽게 넓어진 기능들입니다.

- 학생 개인정보를 서버에 저장하지 않는 게 원래 원칙이었으나, 선생님이 로그인해서 반별 결과를 관리해야 한다는 필요 때문에 원칙을 바꾸고 Supabase 로그인·DB 연동을 새로 구현
- 구글 계정 로그인 추가
- 인쇄 가능한 검사지 리포트, 학급 전체 통계 화면(응시율/해득수준/단계별 평균 그래프) 추가
- 문장·짧은 문단 단계(7~8단계) 추가

## 어려웠던 점 & 시행착오

### 음성 인식이 계획대로 되지 않았던 과정 (가장 오래 걸린 부분)

1. 처음엔 Azure Speech SDK(웹소켓 방식)로 구현했는데, SDK의 `enableMiscue` 옵션이 실제로는 동작하지 않는 **알려진 버그**였음 (마이크로소프트 Q&A에서 동일 증상 확인). 다른 말을 해도 목표 글자로 잘못 인식되는 원인이었음 → REST API로 직접 녹음 파일을 보내는 방식으로 전면 교체.
2. 브라우저 기본 녹음 포맷(`webm/opus`)이 Azure REST API가 공식 지원하는 포맷 목록에 없어서 전부 0점으로 나옴 → Web Audio API로 직접 PCM 샘플을 모아 WAV 파일을 수동으로 인코딩하도록 교체.
3. 채점용으로 목표 글자를 힌트(`Pronunciation-Assessment` 헤더)로 실어 보내면, **인식 결과 자체가 그 힌트 쪽으로 편향되는** 부작용이 있다는 걸 뒤늦게 발견 (Azure 공식 문서도 이렇게 안내함). → 같은 녹음을 힌트 없이/있이 두 번 보내서, 힌트 없는 쪽에서 진짜 인식 텍스트를, 힌트 있는 쪽에서 점수만 가져오는 방식으로 해결.
4. 짧은 한 음절(예: "라")을 정확히 말해도 Azure가 비슷한 다른 소리로 잘못 인식하는 경우가 남아있어, 대체 인식 후보(NBest) 중 정답이 있으면 인정하도록 보완하고, 그래도 안 되면 선생님이 옆에서 듣고 수동으로 정답 처리할 수 있는 예외 버튼을 추가.

### 정상 동작인데 버그처럼 보였던 사례들

- 정확히 발음한 단어인데 유창성(FluencyScore) 감점으로 낮은 점수가 나온 것 → 실제로는 Azure 발음 평가의 의도된 동작이었음. 다만 한 음절짜리 발화에는 "유창성" 지표가 원래 잘 안 맞을 수 있다는 한계는 남아있음.
- "인식된 소리"가 계속 "-"로 나온다는 문제 → 그 필드를 저장하기 시작하기 *이전*에 만들어진 오래된 기록이었을 뿐, 새 코드의 버그는 아니었음. 다만 "-"만 보여주면 고장난 것처럼 보여서 "예전 기록이라 없음"과 구분해 보여주도록 개선.
- 다문화/기초학습지원대상 체크박스가 저장 안 되는 문제 → 코드 문제가 아니라 Supabase에 새 컬럼을 추가하는 마이그레이션 SQL을 아직 실행하지 않은 것이 원인.
- 구글 로그인이 localhost로 튕기는 문제 → 코드는 이미 정상이었고, Supabase의 Redirect URL 설정에 배포 주소가 등록되지 않은 게 원인.

### 환경/인프라에서 부딪힌 문제

- 컴퓨터 이름이 한글("3F교사연구실1")이라 Vercel CLI(`npx vercel dev`)가 내부 오류를 내며 로컬에서 실행이 안 됨 → 순수 Node로 동작하는 `dev-server.mjs`를 따로 만들어 로컬 테스트용으로 사용.
- 브라우저 네이티브 팝업(`prompt`/`confirm`/`alert`)이 이 환경에서 조용히 안 뜨는 문제 → 모든 입력/확인을 화면 안 입력창·2단계 클릭 버튼으로 교체.
- Chart.js를 프로젝트에서 처음 붙여봐서, CDN이 막힌 환경(오프라인 교실 등)에서 흰 화면으로 깨지는 걸 미리 고려하지 못했음 → push 전 코드 리뷰 과정에서 발견해 대비 코드 추가.
- 학생 이름에 특수문자(`<`, `>` 등)가 들어가면 화면이 깨질 수 있는 이스케이프 누락도 코드 리뷰에서 발견해 수정.

### 설계 결정을 되돌리거나 미룬 경험

- "학생 개인정보는 서버에 저장하지 않는다"는 원래 원칙을 학생 관리 기능을 위해 사용자가 직접 변경 결정.
- "1~6단계를 완전히 완성한 뒤에 학생 관리 기능을 붙이자"고 정했다가, 필요에 의해 순서를 바꿔 먼저 구현.
- 문장 단계도 "1~6단계가 안정된 뒤에" 착수하기로 미뤘다가, 채점 방식(Azure 종합 점수 신뢰)을 먼저 정하고 나서 재개.
- 학급통계 화면은 참고했던 다른 프로그램의 기능(1차/2차 회차 구분, 12개 세부항목 등)을 전부 따라가지 않고, 지금 앱 구조에 맞게 범위를 의도적으로 단순화.

## 배운 점

- 음성 인식처럼 외부 API에 의존하는 기능은 "일단 되는 것처럼 보이는" 상태와 "실제로 신뢰할 수 있는" 상태 사이에 여러 단계의 검증이 필요했다 (인식 성공 ≠ 정확한 텍스트, 정확한 텍스트 ≠ 공정한 채점).
- 채점 기준처럼 교육적 판단이 들어가는 부분은 숫자 하나(평균 점수)보다 맥락(어느 단계까지 도달했는지)을 함께 봐야 실제 학생 수준을 더 정확히 반영한다.
- 실제로 브라우저에서 써보기 전까지는 "표가 좁아서 글자가 잘린다", "번호가 중복돼 보인다" 같은 문제를 코드만 봐서는 발견하기 어려웠다 — 매 기능마다 실사용 피드백 라운드를 거친 것이 품질에 크게 기여했다.
