## 기본 원칙

- **특별한 이유가 없으면 `claude-opus-5`를 기본값으로 사용합니다.** 비용을 아끼려고 임의로 하위 모델(Sonnet, Haiku)로 낮추지 않습니다 — 모델 다운그레이드는 품질에 영향을 주므로 팀/사용자가 명시적으로 결정할 사안입니다.
- 사용자가 명시적으로 "소네트 써줘", "하이쿠로" 라고 요청한 경우에만 해당 모델을 사용합니다.
- `claude-fable-5`(Anthropic의 가장 강력한 모델)는 사용자가 명시적으로 요청했을 때만 사용합니다. 가격이 Opus급보다 높고, API 동작 방식(사고 항상 켜짐, 프리필 불가 등)도 다릅니다.

## 어떤 모델을 언제 쓸까

| 용도 | 권장 모델 | 이유 |
|---|---|---|
| 일반적인 코딩, 복잡한 추론, 에이전트 작업 | Opus 5 | 기본값, 품질과 비용의 균형 |
| 대량/저지연 처리, 분류, 단순 요약 | Sonnet 5 또는 Haiku 4.5 | 비용이 낮고 속도가 빠름 (팀 논의 후 결정) |
| 최고 난이도의 장시간 에이전트 작업 | Fable 5 | 가장 강력하지만 비용이 가장 높음, 명시적 요청 시에만 |

## 모델별 특징 요약

- **Opus 5 / Sonnet 5**: `thinking: {type: "adaptive"}`가 기본으로 켜져 있어(파라미터를 생략해도 적응형 사고가 동작) 별도 설정 없이도 복잡한 문제에 대해 스스로 사고 깊이를 조절합니다.
- **Fable 5**: 사고가 항상 켜져 있으며 끌 수 없습니다. `output_config.effort`로 사고 깊이를 조절합니다(`low`~`max`).
- 오래된 모델(Sonnet 4.5, Haiku 4.5 등)은 `thinking: {type: "enabled", budget_tokens: N}` 방식의 고정 토큰 예산을 아직 지원하지만, 신규 코드에서는 권장하지 않습니다.

## 비용 관련 참고

- effort 레벨(`low`/`medium`/`high`/`xhigh`/`max`)로 품질과 비용을 조절할 수 있습니다. 자세한 내용은 [비용 관리](04-비용-관리.md) 문서를 참고하세요.
- 프롬프트 캐싱을 활용하면 반복되는 시스템 프롬프트/도구 정의 비용을 크게 줄일 수 있습니다.
