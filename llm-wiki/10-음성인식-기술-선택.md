# 음성인식 기술 선택

## 결론

**Azure AI Speech의 발음 평가(Pronunciation Assessment)** 기능을 사용한다. Web Speech API는 사용하지 않기로 했다.

## 왜 Web Speech API를 쓰지 않기로 했나

Web Speech API(크롬/엣지 내장 음성인식)는 "사람이 무슨 말을 하려고 했는지"를 맞히도록 만들어진 범용 인식기다. 불완전한 발음도 실제 존재하는 단어로 알아서 보정해서 인식하는 경향이 있다.

예: 학생이 "목욕탕"을 받침을 빠뜨려 "모요탕"이라고 발음해도, Web Speech API는 이를 "목욕탕"으로 보정해서 인식할 가능성이 높다. 우리 앱은 정확히 이런 오류(받침 탈락 등)를 잡아내야 하는데, Web Speech API의 텍스트 비교 방식으로는 오류를 놓치기 쉽다.

## 왜 Azure 발음 평가를 쓰기로 했나

Azure 발음 평가는 "무슨 단어인지 맞히기"가 아니라, **목표 텍스트(예: "목욕탕")를 미리 주고 학생이 낸 소리가 음소 단위로 그 목표와 얼마나 일치하는지**를 계산하도록 만들어진 기능이다. 받침이 빠지거나 다르게 발음된 지점을 정확히 낮은 점수로 짚어낼 수 있어 우리 프로젝트 목적(발음 오류 진단)에 맞다.

- 음소/음절/단어 단위로 정확도 점수(0~100) 제공, 한국어 지원
- 계정 가입과 API 키 발급이 필요하고, 무료 사용량이 있지만 정확한 조건은 가입 시 확인 필요
- Web Speech API보다 연동이 복잡함 (이후 개발 단계에서 하나씩 풀어간다)

## 개인정보 설계 원칙

- 학생 이름·학번 등 식별정보는 음성 요청과 **절대 함께 전송하지 않는다.**
- 세션은 이름이 아니라 "학생1", "학생2" 같은 임시 라벨이나 브라우저 로컬 저장 정도로만 구분한다.
- 서버(Azure)로는 음성과 목표 텍스트만 오가며, 그 외 개인정보는 오가지 않도록 설계한다.

## API 키 보관 방식 (결정)

Azure Speech 키는 Stripe의 publishable 키 같은 "공개해도 되는 키" 구분이 없다. 발급되는 키는 전부 secret 키이며, 브라우저 코드에 그대로 넣으면 페이지 소스로 누구나 볼 수 있다.

지금은 **프로토타입 단계**이므로 키를 HTML/JS 파일에 직접 넣고 시작하되, 아래 원칙을 지킨다.

- 이 파일은 선생님만 로컬에서 실행한다 (링크 공유·인터넷 게시 금지).
- Azure 포털에서 해당 리소스에 사용량/비용 한도(예산 알림)를 걸어둔다.
- 테스트가 끝나거나 유출이 의심되면 키를 재발급(rotate)한다.
- 나중에 실제로 배포(다른 사람과 공유)하게 되면, 그때는 키를 서버에만 두고 브라우저에는 짧은 시간만 쓰는 토큰을 내려주는 중계 서버 방식으로 바꾼다.
