# 앱 설계 개요 — 자모→음절→단어 발음 지도 앱

[07-발음지도-참고자료-요약](07-발음지도-참고자료-요약.md)과 [08-찬찬한글-참고자료-요약](08-찬찬한글-참고자료-요약.md)을 바탕으로 정한 프로토타입 설계 방향. 새 기능을 만들 때 이 문서의 흐름을 기준으로 삼는다.

## 전체 학습 단계 (앱의 큰 트랙)

1. **모음** — 기본모음 5쌍(ㅏㅓ → ㅗㅜ → ㅡㅣ → ㅑㅕ → ㅛㅠ), 자음보다 먼저 배운다.
2. **자음** — 조음 위치별 묶음(ㄱㅋㄲ / ㄴㄷㅌㄸ / ㅁㅂㅍㅃ / ㅅㅈㅊㅉㅆ / ㅇㅎㄹ).
3. **받침 없는 음절·단어** — 자모 합성("민글자"). 의미단어 + 무의미단어를 섞는다.
4. **복잡한 모음(이중모음)과 그 단어** — ㅐㅔ, ㅘㅝ 등.
5. **대표받침 7개** — ㄱㄴㄷㄹㅁㅂㅇ, 음절 단위부터.
6. **복잡한 받침(받침가족·겹받침)** — 표기와 발음이 달라지는 경우(음운변동) 포함.
7. **(나중에) 문장 단계** — 프로토타입이 잘 작동하는 걸 확인한 뒤 추가.

지금은 1~3단계(자모→받침없는 음절·단어) 프로토타입부터 만든다.

## 문항 하나의 화면 흐름

1. **듣기(이해하기)**: 목표 글자/단어를 화면에 보여주고 TTS로 모범 발음을 들려준다.
2. **따라 말하기**: 학생이 마이크 버튼을 눌러 따라 말한다 (Web Speech API 음성인식).
3. **확인하기**: 인식된 소리와 목표를 비교해 정답/오답을 피드백하고, 다시 듣기·다시 시도를 제공한다.

## 문항 구성 원칙

- 의미단어뿐 아니라 **무의미 단어**도 섞어서 학생이 진짜 소릿값을 아는지 확인한다.
- 받침 난이도는 **대표받침 → 받침가족 → 겹받침** 순 계단식으로 올린다.
- 음운변동(연음, 비음화, 구개음화, ㅎ탈락 등) 유형은 받침가족 단계 이후 반영한다.
- 한 세션은 짧고 반복적으로 구성한다 (이미 아는 것 위주 + 새 것 소량).

## 기록/진행 관리

- 학생별 진도·정확도는 기기 로컬에만 저장한다 (서버 전송 금지 — [00-프로젝트-에이전트-가이드](00-프로젝트-에이전트-가이드.md) 원칙과 동일).
- 정확도가 낮은 자모/받침을 표시해두면 선생님이 학생 수행수준을 파악하는 데 참고할 수 있다.

## 아직 정하지 않은 것

- 쓰기 활동 포함 여부 (익힘책은 쓰기를 강화하지만, 앱은 듣기·말하기 중심으로 갈 수도 있음)
- 정확도 판정 기준(완전 일치 vs 유사도 허용 범위)
- 학생용 캐릭터/UI 톤
